# Agent Note: Windows orphan descendant termination

Status: implemented

[English](2026-08-29-windows-orphan-descendant-termination.md) | 中文

## 问题

在 POSIX 上，`terminate()` 向 detached 进程组发信号，因此能到达组内每个成员——包括比直接子进程活得更久的后代。在 Windows 上，终止曾经是一次盲目的 `taskkill /PID <pid> /T /F`，它要求根进程仍然存活。根进程在脱离的后代仍在运行时自然退出（exit 0）会使 `treeAlive()` 报告 false，`terminate()` 便不做任何事直接返回：后代永远运行下去。grace 升级也因同样的原因在直接子进程结算时被取消，尽管注释声称它会存活下来。取消一条启动了后台进程的 bash 命令，在 Windows 上会让该进程继续运行，而完全相同的场景在 POSIX 上会被回收。

## 决策

Windows 终止现在是由 `dsh-subprocess-local` 拥有的身份围栏清扫：

- spawn 时，从进程表捕获根进程的创建时间身份（经 koffi 绑定调用 `GetProcessTimes`）。
- 每个终止档——`terminate()` 的第一次清扫与 grace 之后的重扫、`terminateForHostExit()`、以及 abort 监听器——运行同一次清扫。身份仍然匹配的存活根用 `taskkill /T /F` 终止（与之前的整树击杀相同）。根一旦消失——包括其状态因句柄未释放而仍可读的已退出根，以等待状态区分——清扫从根 pid 的子层遍历进程表（后代仍以 `th32ParentProcessID` 指向已消失的根），逐一强制终止每个幸存者，并在击杀前立即再次核验其创建身份，使"已退出且 pid 被复用"的候选被跳过而非被误杀。
- `hasLiveWork` 以只读方式回答同一问题：等待路径用它来释放 grace 之后的升级（以及持有事件循环的 ref 定时器）——一旦再无可达目标即释放，而不是等到直接子进程结算时。
- 是否武装跟随清扫结果：终止了某物的档保留重扫承诺；什么都没找到的档——或根 pid 的占有者已不匹配的档——不武装任何东西。
- POSIX 路径不变：组探测、直接子进程回退、`kill()` 上的组存活门控，语义逐字节保留。在没有可用清扫的环境中（非 Windows 主机运行 win32 语义测试），旧有的按 pid 终止回退保留原有边界。

spawn 时根身份不可读会回退为对存活根的按 pid 终止——即今天的行为——而不是拒绝终止。

## 备选方案

**保留 `taskkill /T` 并接受缺口。** 否决：孤儿泄漏正是缺陷本身；Windows 是主要开发平台，每条守护化了子进程的被取消命令都会观察到这一不一致。

**扩展等待边界：让 `waitForExit` 等待后代死亡。** 否决：这会改变已成文档的等待契约，且不可杀的后代会让等待挂起；等待仍停留在直接子进程，回收由清扫负责。

**不做身份围栏、直接沿父链接击杀。** 否决：仅凭父链接，被复用根 pid 的子进程与已退出根的孤儿无法区分；逐候选的创建身份再核验与根身份匹配才是清扫可以安全瞄准的原因。

**用 Job Object（`AssignProcessToJobObject`）获得真正的树语义。** 暂缓：它要求向每个子进程注入句柄并处理 breakaway，是更大的底层改造；带身份围栏的父链接清扫在现有原语内补齐了缺口。若未来出现能打破父链接的后代（Windows 上今天不存在），再重新评估。

## 后果

Windows 终止现在能到达与 POSIX 组信号相同的后代集合，取消命令会在两个平台上同样回收进程树。每个终止档的成本是一次 Toolhelp32 快照加每个候选一次进程状态读取，被拆卸窗口约束。残余逃逸与 POSIX 探测设计共享：最终清扫之后才启动的后代，以及因根 pid 双重复用而无法区分的孤儿——两者都会被跳过，绝不会被误杀。这次清扫还修复了 `terminateForHostExit()` 中一个潜在隐患：它此前会盲目强杀根 pid，在宿主退出时可能命中被复用的 pid。

## 测试

- `windows-inspector` 单元测试在任意主机上钉住清扫契约：存活根击杀、复用根拒绝、不可读身份回退、children-first 孤儿清扫、句柄未释放的已退出根、快照到击杀之间的复用跳过、只读 `hasLiveWork`。
- `spawn` 接线测试（注入清扫与注入平台）钉住 spawn 侧决策：spawn 时捕获身份、第 1 档加恰好一次 grace 后重扫、缺席树不武装、等待路径绝不终止、等待观察到无活体时释放升级。
- 真实 Windows 集成测试 spawn 一个自然退出且留有存活后代（pid 写入文件）的根，断言 `terminate()` 经真实 koffi 进程表回收该后代。
